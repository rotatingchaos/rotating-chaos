# Security Policy

## Rotating Chaos

Rotating Chaos takes the security and privacy of our guild members seriously.

The website includes member authentication and community features powered by Firebase and other third-party services.

## Reporting a Security Issue

If you discover a security vulnerability, please do **not** report it publicly through GitHub Issues, Discord public channels, Chaos Chat, or other public areas.

Please report security concerns privately to the Rotating Chaos site administrator or guild leadership.

When reporting an issue, please include:

- A description of the problem
- The page or feature affected
- Steps needed to reproduce it, where possible
- Screenshots or other useful information
- What you believe could be accessed or affected

Please do not attempt to access, alter, delete, or download another member's information while investigating a possible vulnerability.

## What Counts as a Security Issue?

Examples include:

- Authentication or login bypasses
- Access to guild-only areas without authorisation
- Access to another member's private or restricted information
- Firestore security-rule vulnerabilities
- Ability to create, edit, or delete content without the required permission
- Member, Officer, or Admin privilege escalation
- Exposed private credentials or secrets
- Vulnerabilities affecting Chaos Chat, Events, run sheets, profiles, gallery content, posts, or other member features
- Other vulnerabilities that could compromise the website or its members

## What Is Not a Security Issue?

Normal website bugs should not be reported as security vulnerabilities.

Examples include:

- Broken links
- Layout or mobile-display problems
- Spelling mistakes
- Missing images
- Incorrect guild information
- Feature requests
- General content corrections

These can be reported to the Rotating Chaos team normally.

## Supported Version

Security fixes are applied to the current live version of the Rotating Chaos website.

Older copies, forks, downloaded versions, or modified versions of the project are not supported.

## Credentials and API Keys

Private credentials, passwords, API secrets, access tokens, and other sensitive authentication information must never be committed to this repository.

Some third-party services use public client-side configuration values as part of normal website operation. Where applicable, those credentials should be restricted through the relevant provider and granted only the permissions required by the website.

## Responsible Disclosure

Please give the Rotating Chaos team a reasonable opportunity to investigate and correct a reported vulnerability before sharing details publicly.

Thank you for helping us keep the Chaos chaotic for the right reasons.
